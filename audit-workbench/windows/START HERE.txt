AUDIT ANALYTICS WORKBENCH - START HERE
======================================

What this is
------------
A program that checks SAP extracts for the Annexure-I audit topics of
Office Circular No. 53 and prepares the Working Paper and a pre-filled
Annexure-II in Excel. It works entirely on this computer: no internet,
nothing is uploaded anywhere.


ONE-TIME SETUP (about 5 minutes)
--------------------------------
1. Python must be installed on the computer (IT can do this).
   - Installer: python.org > Downloads > Windows > "Windows installer (64-bit)",
     version 3.11 or newer. It can be downloaded on any internet computer and
     copied to the office computer.
   - Run it with the default options. Ticking "Add python.exe to PATH" is
     recommended.

2. Copy this whole "AuditWorkbench" folder to the computer, for example to
   Documents. Keep the folder together; do not move files out of it.

3. Double-click  Install  (once only). A black window shows progress and
   says "Installation complete". Press any key to close it.


EVERY TIME
----------
1. Double-click  Run Audit Workbench.

2. First time? Press "Try with demo data", then RUN ANALYSIS. This uses a
   made-up company so you can see what the results look like.

3. For a real audit, go through the four tabs from left to right:
     1. Audit details  - company, period, cut-off date
     2. Topics         - tick the sixteen Annexure-I topics
     3. SAP files      - choose the exported SAP files; reports marked
                         NEEDED are required by the ticked topics.
                         Copy from SAP the row count and the total shown for
                         each report into the two boxes under it.
                         If a file's columns are not recognised (common with
                         Z-reports), press "Columns..." and pick them once.
     4. Settings       - change thresholds only where the company's rules
                         differ (e.g. the DoP / tender limit)
   Press "Check my files" to see whether the files were read correctly and
   whether they agree with the SAP row counts / totals, then RUN ANALYSIS.

   Starter settings for SAIL CMO 2025-26 are in the "profiles" folder:
   "Open saved audit..." and choose SAIL_CMO_2025-26.toml.

4. "Self-test" re-checks every rule on built-in made-up data. Run it once on
   each new computer; it must say "Self-test passed".

5. The results folder opens with:
     WorkingPaper_....xlsx   evidence for every test
     AnnexureII_....xlsx     the plan in the OO-53 format, pre-filled
     audit_settings.toml     the settings used (open it again next time with
                             "Open saved audit...")


GOOD TO KNOW
------------
- Results are red flags, not audit observations. Every exception must be
  verified in the field (OO-53 para 10).
- "NOT EXECUTABLE" means a file, a column or a criterion was missing. It is
  NOT the same as "no exceptions".
- "NIL - NOT RECONCILED" means no exceptions were found, but the SAP row
  count / total were not entered or did not agree. It is NOT assurance.
  "NIL - PARTIAL COVERAGE" means part of the population could not be tested
  (e.g. returns whose sale date is unknown). It is NOT assurance either.
  Only "NIL - RECONCILED" counts as analytical assurance, and a topic is
  assured only if every test for that topic says "NIL - RECONCILED".
- "BLOCKED" means a criteria or master file has duplicate or overlapping
  records (e.g. two prices for the same material and date). Correct the
  file and run again.
- Each test shows its "coverage", e.g. how many credit notes could be linked
  to the original invoice. Low coverage means a weaker result.
- Never email or upload the SAP files or the results outside the office.
